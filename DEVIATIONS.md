# Deviations from SPEC.md

Where SPEC.md turned out to conflict with reality or with a hard constraint, the code follows
reality and the change is logged here. Evidence is in `REALITY_REPORT.md`.

| # | Spec says | We do | Why |
|---|---|---|---|
| 1 | `Verdict` is a frozen dataclass with `.model_dump()` | Frozen pydantic `BaseModel` | `.model_dump()` is a pydantic method; dataclasses don't have it. Matches the SDK's own frozen answer models. |
| 2 | Runtime dep `pydantic>=2` | `pydantic>=2.12` | `typesafe-sdk` 0.7.1 requires it. |
| 3 | SDK package unnamed | `typesafe-sdk>=0.7.1,<0.8` | The official package. It had breaking changes in both 0.6 and 0.7, so we pin the minor version. `typesafe-ai` on PyPI is an unofficial third-party shim and is not used. |
| 4 | Every primitive has three fields incl. `confidence` | Noul answers have only `noul`; `JevAnswer.confidence` is optional | Real API shape. A noul's probability is used as its risk directly. |
| 5 | Flat "$0.0004 per check" | Cost is computed per call from `usage.input_tokens` × $0.042/1M | $0.0004 implies about 9.5k tokens per check; real guard checks are about 300–1,500 tokens. Falls back to a chars/4 estimate if usage isn't reported. |
| 6 | (implicit) SDK client built with `Guard(...)` | Built lazily on the first check | Since 0.7.1 the SDK validates the key in its constructor. Lazy creation means `Guard(...)`, `policy show` and `validate` work without a key. |
| 7 | Nightly GitHub Action runs the golden eval against real Jev (~$0.20/run) | Removed; the eval runs locally only, on demand | Owner requirement: no API key is ever stored in CI, so the open-source repo can never bill the maintainer. |
| 8 | Integration tests gated on `TYPESAFE_API_KEY` | Gated on `TYPESAFE_API_KEY` **and** `JEV_GUARD_ALLOW_LIVE=1`, plus a 200k-token budget per session | Having a key in your shell for other reasons shouldn't be enough to spend money. |
| 9 | Layout has no module for `Guard` | Added `src/jev_guard/guard.py` | `guards/input_guard.py` and `guards/output_guard.py` hold the per-stage request builders; the public class needed its own home. |
| 10 | Section 5 rules ("review if X > t") vs Section 6 ("medium/low don't drive action alone") | Single-question review rules are `high` severity with weight 2.0 and `review_threshold` 1.0 | So one fired `high` question means review and several can block (when a policy sets `block_threshold`). Rejected alternative: summing raw probabilities, because one strong signal gets diluted when a policy has 5+ questions. |
| 11 | (unspecified) Behaviour when Jev is down | Checks raise `JevAPIError` | Rejected fail-open (it silently disables safety) and fail-closed (a Jev outage takes the app down). The app decides. |
| 13 | Section 5: "`from_builtin` and `from_yaml` produce equivalent behavior on the golden dataset" | Until Phase 5: identical `model_dump()`, and identical aggregation on 300 seeded random answer sets per policy and stage. A drift test fails if a YAML twin goes stale | The golden dataset doesn't exist until Phase 5. Random answers cover threshold edges more densely than 100 real samples would. |
| 14 | (unspecified) YAML format | Keys mirror `Policy` fields; `extends: <builtin>` merges per question and `null` removes an inherited question | Lets Marcus change one threshold without copying 150 lines. The builtin twins are still complete, standalone files. |
| 15 | Section 5 `rag`: "fall back to general behavior on the output" | New `context_fallback` policy field (rag sets `general`). Guard logs a warning and appends a reason noting the fallback | Keeps the behavior expressible in YAML instead of hardcoding it in a Python subclass. |
| 16 | Section 5 lists questions but not stages or severities for some | `support_agent`: `frustration_level` and `should_escalate_to_human` run on **input**, and `contains_refund_promise` is `high` (review). `coding_agent`: `network_egress_intent == write` and `attempts_privilege_escalation` are `high`, and `block_threshold` is 3.0. `rag`: grounded, hallucination and contradiction are `high` with `block_threshold` 3.0; citation is `low` and context-sufficiency is `medium` | Spec gives no rule for these. Privilege escalation isn't critical because dev tools use sudo legitimately; contradiction isn't critical because one uncertain signal shouldn't hard-block a bank's answer. `coding_agent_prod.yaml` shows the stricter setup. |
| 17 | `QuestionSpec.kind` (internal name) | `type` | Matches the Jev wire format and the Section 7 linter message ("unknown question type"). |
| 18 | (unspecified) What integrations do on `block` | `@guarded` returns the policy's safe reply string. `wrap_openai` / `wrap_anthropic` / the LangChain handler raise `GuardBlockedError` (carries `.verdict` and `.suggested_response`) | A decorated `prompt -> str` function can return a safe string transparently. Rejected for the client wrappers: fabricating a `ChatCompletion` / `Message`, because callers reading `id` or `usage` would get made-up data. |
| 19 | "`@guarded` decorator + monkey-patch helper" | Integrations are duck-typed and don't import `openai` / `anthropic`. `wrap_openai` covers `chat.completions.create` and `responses.create`, sync and async. With `stream=True` the wrappers check input only and log a warning until Phase 6 streaming lands | Installing jev-guard never pulls in an LLM SDK. The Responses API is OpenAI's current primary API, so skipping it would miss many users. |
| 20 | LangChain in `[langchain]` extra | Also in `[dev]` extra | Needed to type-check and test the callback in CI. Users still only get it via `[langchain]`. |
| 21 | Entry point `jev_guard.cli:app`; Typer in `[cli]` extra; Section 15 "`pip install -e .` → `jev-guard --help` works" | Entry point `jev_guard.cli:main`, a shim that loads the Typer app from `_cli_app.py` or prints `pip install "jev-guard[cli]"`. Also `python -m jev_guard` | The spec's items conflict: without the extra, an entry point pointing straight at a Typer app crashes with an ImportError. Rejected making Typer and Rich core deps: ~3 MB for library-only users. |
| 22 | (unspecified) Cost safety for `scan` | `scan` estimates cost locally first and refuses above `--max-cost` (default $1.00). It stops mid-run at the cap (failed calls release their reservation), and `--dry-run` makes no calls | A mistyped path to a large log shouldn't silently spend money. |
| 23 | `scan` / `check` flags | Added `scan --dry-run --max-cost --concurrency` and `check --output --context --json --fail-on`; `check` exits 3 when `--fail-on` triggers | Shell scripts need a machine-readable result. A block isn't an error, so it doesn't exit 1. |
| 24 | Section 7 `eval` command in Phase 4 | Lands in Phase 5 with the golden runner and dataset | It has nothing to run until then. |
| 25 | Layout | Added `eval/logs.py` (format detection), `eval/scan.py` (batch engine), `eval/metrics.py` (P/R/F1 shared by scan and eval) | Keeps `report.py` about rendering only. |
| 26 | Langfuse / Arize "detect by header" | Detected from the first record's keys (`projectId`/`traceId`/`sessionId` → Langfuse; `attributes.*`/`context.span_id` → Arize OpenInference) | Extraction is best-effort: both vendors' export shapes vary by SDK version. Not yet verified against real exports from either. |
| 27 | Phase 5 "50 jailbreaks from OWASP LLM Top 10 + garak + promptbench" | 50 hand-written samples that *reproduce the attack patterns* those projects catalogue (9 categories); none are copied | Avoids licence questions and training-data overlap with public jailbreak lists. Each sample records the pattern it follows in `source`. |
| 28 | Clean set: "~30 benign" | 15 everyday requests + 15 **hard negatives** that look like attacks but aren't ("Ignore the typo…", "Pretend you're a pirate…", "What is prompt injection?") | False positives decide whether teams keep a guardrail. Easy negatives would inflate precision. |
| 29 | PII: "synthetic values, never real" | Enforced by a test that scans every sample and allows only reserved values (example.com / .test, 555-01xx, card-network test numbers, SSNs in never-issued ranges). The test also proves each detector fires on a realistic value | "Never real" needs a check, not a promise. |
| 30 | Manifest minimums | Marked `"provisional": true`; values are my estimates (e.g. injection precision 0.85 / recall 0.80) | No real Jev run has happened. Replace them with measured values minus a margin after the first run, then set `provisional` to false. |
| 31 | `eval` exit code "non-zero" | Exit 4 below a minimum (1 is user error). An eval that judged zero samples fails, never passes | CI can tell "the guard regressed" from "you mistyped a path". |
| 32 | Datasets | Generated by `scripts/build_golden_dataset.py` and checked by a drift test; shipped inside the wheel at `jev_guard/eval/datasets/` | `jev-guard eval` works from a plain pip install. Exact JSON escaping and base64/ROT13 payloads. |
| 33 | Section 10 `stream_check_every` / strategy choice, with `astream_check(llm_stream, user_message)` frozen | Policy fields `stream_strategy` ("buffer" \| "rollback") and `stream_check_every` (default 40), settable in YAML | Keeps the frozen signature and lets Marcus change streaming behaviour without code. |
| 34 | "yield a special sentinel token" (rollback) | Both strategies end a stopped stream with a `StreamCut`, a `str` subclass carrying `.verdict` and `.retract` (True in rollback) | Naive apps that join tokens still show a readable notice. Cooperating apps get the "message removed" signal. Rejected raising mid-stream: it crashes zero-config apps. |
| 35 | (unspecified) What each streaming check covers | The whole response so far, not just the new chunks. Cost grows roughly quadratically (measured: $0.0009 for 1k chunks, $0.0066 for 3k at every=40) | Otherwise an instruction split across two check windows is never seen whole. Documented with measured numbers; raise `stream_check_every` for long outputs. |
| 36 | Phase 3 wrappers checked input only with `stream=True` | `wrap_openai` / `wrap_anthropic` now return a stream wrapper that yields the SDK's own chunk objects, output-checked, raising `GuardBlockedError` on block; other stream attributes pass through | Priya's "does it break streaming?": it doesn't, and the streamed output is now guarded too. |
| 37 | Section 9 `found[i]["value"] == "***"` | `value` is the placeholder that replaced the match (`[EMAIL]`, `[PHONE]`, `[SSN]`, `[CARD]`, `[REDACTED]`), never the original | Typed placeholders keep redacted text useful as LLM input. The original value is still never exposed. |
| 38 | Section 9 strict: "a single Jev call on any chunk the regex didn't touch" | One Jev call over **every** sentence, with regex hits already masked; a flagged sentence is replaced whole | Otherwise "Jane Doe, jane@x.com" becomes "Jane Doe, [EMAIL]" and the name survives, which defeats the purpose for Marcus's compliance use. Jev classifies but doesn't locate words, so redaction is sentence-granular (over-redacts rather than under). |
| 39 | Section 8 context manager "shared telemetry" | `with Guard() as g:` opens a `jev_guard.session` parent span; each Jev call is a child `jev_guard.check` span. Checks skipped without a Jev call (empty text) emit no span | Groups a request's checks in a trace viewer. |
| 40 | README Credits: "link Armin Ronacher's post about using Jev for agent monitoring" | No such post exists. The "track agent traces and prevent jailbreaks" remark is **Diogo Almeida's**, in [TechCrunch's launch coverage](https://techcrunch.com/2026/09/18/a-new-kind-of-ai-model-from-a-chatgpt-inventor-is-thrilling-developers/); Ronacher is quoted in the same article on acting on probabilities. Credits attribute each correctly and link that article | Misattributing a quote in a launch README is the kind of error that costs credibility. |
| 41 | README cost math "10,000 checks/day with support_agent ≈ $4/day" | "10,000 conversations/day (20,000 checks) ≈ $0.37/day", computed by the library's estimator on a typical exchange | See #5. The spec figure is ~20× too high. |
| 42 | `integrations/litellm_proxy.py` in the layout, never scheduled in a phase | Built in Phase 7 against LiteLLM 1.102's `CustomGuardrail` (`async_pre_call_hook` / `async_post_call_success_hook`), rejecting with a `ValueError` subclass as LiteLLM's docs prescribe | The "Deploying behind LiteLLM proxy" recipe needed real code behind it. Streaming output through the proxy isn't checked in v0.1. |
| 43 | Coverage badge; nightly eval badge | Static coverage badge (99%) until a coverage service is connected; no eval badge until real numbers exist | A badge must not claim results that were never measured. |
| 44 | Docs pages | Added `streaming.md`, `telemetry.md`, `redaction.md`, `cli.md` beside the spec's pages. A test loads every policy YAML snippet in the docs | Marcus's audit and compliance questions need reference pages; docs examples mustn't rot. |
| 45 | Packaging | Version read from `jev_guard/__init__.py`. The sdist excludes SPEC, REALITY_REPORT, LAUNCH, and CI files. CI builds, runs `twine check --strict`, and smoke-tests a no-extras install. mkdocs pinned `<2` | Mkdocs-material warns that MkDocs 2.0 breaks its plugins and themes. |
| 46 | Section 4 freezes `Guard`'s methods | Multi-turn and agent checks are new modules (`jev_guard.conversation`, `jev_guard.agents`) built on `Guard` internals; `Guard` gained no methods | Closes the two biggest real gaps (jailbreaks split across turns; indirect injection and hijacked tool calls) without breaking the frozen contract. |
| 47 | Verdict `stage` is input/output only | Tool **results** are `input` (untrusted content entering the model), tool **calls** are `output` (actions the model takes) | Matches data flow, and keeps `Verdict` unchanged. |
| 48 | (new) `agent_tools` builtin | Critical: injected instructions, exfiltration requests, destructive calls, credential access. High: secrets in results, sending data out, consequential actions, `fits_user_request` (asked only when the user's request is known). `block_threshold` 3.0 | Consequential actions aren't critical because many agents exist to send email or book things. |
| 49 | (new) Claude Code hook | Blocks with exit code 2, uses JSON only for `permissionDecision: "ask"`, and prints nothing on allow | Claude Code treats hook JSON that fails its schema as a non-blocking error and **proceeds**, so JSON-based blocking could fail open. On allow it never outputs `"allow"`, which would bypass the user's own permission rules. |
| 50 | Jev is the only backend | Backends are pluggable (`jev_guard.backends`): Jev, local models, an LLM judge, fallback chains. Chosen process-wide via `set_backend()` / `JEV_GUARD_BACKEND` / `--backend`, never a `Guard` kwarg | Removes single-vendor risk (Jev is a week old, signups closed, 1,200 req/min), and adds offline and private operation for local-model users. A `Guard(policy, backend=...)` kwarg would break Section 4's freeze. |
| 51 | `JevResult` has no cost | Added `cost_usd`, used by the verdict when set | An LLM judge and a local model aren't priced like Jev, and a cache hit costs nothing. Cost reporting must stay honest per backend. |
| 52 | (unspecified) Scale | Cache on by default (1,024 entries, 1 h), client-side rate limit on Jev (1,100/min, TypeSafe allows 1,200), parallel input checking, tool skip-lists | The published limit is ~20 checks/second, which a busy product exceeds. Caching and skip-lists cut spend; parallel checking removes the latency cost of input checks. |
| 53 | Local backend latency | Documented as measured (~6 s per `general` check on a 4-thread CPU), after batching the zero-shot passes cut it from ~8.5 s | The first draft claimed "0.2–1 s" from intuition; measuring showed otherwise. Offline is for batch work, privacy, and fallback, not latency-critical paths. |
| 12 | Choice rule "`intent == malicious` AND its confidence > 0.8" | Implemented exactly; the choice's *risk* for `confidence` is the summed probability of its flagged labels | Keeps `confidence` informative when Jev picks `borderline` but still puts real weight on `malicious`. |
